# 캐릭터 렌더링 끊김 개선 · 2026-10-31

GPU 메시 캐시가 찰 때 전체를 비우던 처리를 없애고, 같은 NPC의 파트마다 반복하던 스켈레톤 평가를 합쳤다. 모델·재질·애니메이션 샘플 빈도(15Hz)·후처리·해상도는 유지했다. x64 Release 빌드를 완료했다. 실행 파일은 `x64/Release/SimpleGame.exe`다.

## 확인한 원인

사용자 PC의 기존 `render_2026_10_20_18_28_30_669_27436_frames_0.csv` 101프레임은 평균 프레임 간격 328.92ms, 렌더 CPU 시간 316.65ms였다. 프레임당 평균 91.41개의 메시가 GPU 캐시에서 제거되고 약 9.20MB가 업로드됐다. 과거 실행 로그이며 이번 비교 테스트와 직접 같은 장면은 아니다.

기존 GPU 저장소는 8MiB였고 용량 초과 시 **모든** 캐시를 비웠다. 세밀해진 사람 파트와 애니메이션 변형이 들어오면 정적 메시까지 함께 잃어버려 파일 읽기·메시 복사·업로드가 되풀이됐다. CPU 포즈 저장소도 삽입 순서로 제거하여 최근 사용 여부를 반영하지 않았다.

## 변경

- GPU 저장소는 장치 한도 이내, 최대 128MiB. 최근 사용 순서를 관리하며 오래 사용하지 않은 메시의 영역만 반환한다. 인접 빈 영역은 합쳐 재사용한다. 사용 중인 정점 영역을 덮기 전 대기 배치를 제출해 painter order를 보존한다.
- CPU 포즈 저장소는 최대 192MiB/1,024개이며 최근 사용 순서로 제거한다. GPU에 이미 있는 포즈는 CPU 캐시가 없어도 바로 그린다. 전체 시스템/VRAM 사용량의 상한을 의미하지는 않는다.
- 연속된 모듈 파트가 같은 GLB를 사용할 때 `Model::SampleMeshes`로 한 번의 뼈대 평가와 스킨 팔레트를 공유한다. 파트 순서 및 같은 깊이의 면 정렬 순서는 유지한다.
- 역바인드 행렬은 로딩 시 한 번 해독한다. 가중치가 0인 본 변환은 생략하며 같은 면의 표시 색상을 정점마다 반복 계산하지 않는다.
- 스키닝 결과·배치 포맷이 같아 기존 디스크 메시 캐시는 계속 사용할 수 있다. 신규 캐시 이벤트는 `mesh_evict`이며 전체 초기화 이벤트 대신 개별 제거를 기록한다.

## 측정

`tests/ArtRenderBenchmark.cpp`: 동일한 Art 파일, 48명, 네 방향, Idle/Walk/Run, 1440×900, 기본 HDR 후처리. MSVC x64 `/O2 /MD`, RTX 4060 Ti. 앞 120프레임 준비 후 뒤 120프레임 측정. 벤치마크만 `glFinish`를 사용해 GPU 완료까지 포함했다. 게임 코드에는 동기 대기를 추가하지 않았다.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 준비 구간 평균 | 43.89ms | 12.80ms |
| 준비 구간 p95 | 83.79ms | 45.10ms |
| 준비 후 평균 | 44.96ms | 6.10ms |
| 준비 후 p95 | 84.17ms | 12.51ms |
| 준비 후 프레임당 업로드 | 12.50MB | 4.11MB |
| 준비 후 GPU 메시 캐시 적중 | 2.25 | 33.00 |

이 장면에서 준비 후 평균 처리 시간은 86.4% 감소했다. 캐시 교체가 완전히 사라진 것은 아니다. 특히 처음 보는 조합의 준비 구간에는 비용이 남는다. 측정에는 게임의 월드 시뮬레이션·세이브·입출력·VSync가 포함되지 않으므로 전체 게임 FPS나 모든 장면의 무끊김을 보장하는 수치가 아니다.

프레임 0/59/119/239의 최종 RGBA를 비교했다. 각 색상 채널의 최대 차이는 8비트 값 1이며, 평균 차이는 약 0.000003 미만이었다. 모델 외형·후처리 설정을 낮추지 않은 상태의 렌더링 반올림 수준이다. 같은 실행에서 반복한 프레임 사이에도 이 수준의 차이가 있었다.

측정 요약과 GPU/빌드 정보는 `docs/performance/2026-10-31-art-render.json`에 보관했다.

## 검증·재측정

- `RenderBatchTests`: 캐시 파일 검사 및 정점 영역 할당·해제·양쪽 병합·단편화, 무작위 10,000회 비중첩 검사 통과.
- `ArtAssetTests`: 전체 카탈로그/클립 샘플링, 모듈 일괄 평가와 개별 평가의 정점·재질·순서 동일성, 잘못된 메시 이름 거부 검사 통과.
- `SimpleGame.sln`: x64 Release 빌드 성공. 기존 `LevelOne` 등의 숫자 변환 경고는 남아 있다.
- 기존 사용자 세이브를 열거나 변경하지 않았다. 테스트의 디스크 캐시/프로파일은 `x64/perf/<label>-data`로 격리했다.

재측정: 저장소 루트에서 `powershell -File tools/Measure-ArtRenderer.ps1 -Label check` 실행. Visual Studio C++ 도구와 게임의 freeglut/glew DLL이 필요하다. 현재 소스를 빌드하고 숨겨진 OpenGL 테스트 창으로 측정한다. 결과는 `x64/perf/check.txt`와 격리된 CSV에 저장된다. 수정 전 결과 재현에는 수정 전 소스가 필요하다.
