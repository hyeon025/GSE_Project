# 캐릭터별 색상·표정

NPC가 같은 얼굴과 색으로 보이던 문제를 피부 5종, 머리색 8종, NPC 의상/장식 배색 12종, 표정 6종으로 구분했다. 기존 파츠 37개와 뼈·키프레임은 공유한다. 플레이어는 별도 파츠 조합과 청록/금색의 전용 0번 배색, 짙은 푸른 머리, 의지가 드러나는 표정을 사용한다.

NPC의 고유 ID를 2,880개 색상/표정 조합으로 안정적으로 매핑한다. 외형 버전 2로 전환할 때 기존 `artParts`는 유지하고 `artPalettes=[skin,hair,cloth]`를 저장한다. 표정은 같은 영속 ID에서 계산하므로 재실행·이동·직업 변경으로 바뀌지 않는다. `GSE_WORLD 6`의 기존 필드를 사용한다. 플레이어의 의상 0번은 NPC 자동 배정에서 제외한다.

두 공용 머리의 5개 상대 모프가 기본 미소 포함 6개 표정을 만든다. `Model::SampleMeshes`가 모프 POSITION 델타를 스키닝 전에 적용한다. 타깃별 정점 수를 확인하고 이름으로 표정을 찾는다. 원본 `.blend`, 정적 머리 GLB 2개, 정적 라이브러리와 사람/주민/망자 리깅 GLB를 동기화했다.

색상은 포즈와 별개로 GPU 인스턴스에 전달한다. 재질 역할과 면 조명을 정점에 인코딩하고 피부/머리/의상/장식의 선형 RGB 네 개로 표시한다. 캐시 키에 색상 번호를 넣지 않으므로 같은 파츠·표정·방향·포즈는 색이 달라도 같은 투영 메시를 사용한다. 인스턴스 크기는 112→176바이트, 속성 수는 7→11개이며 기존 정점 버퍼 형식은 유지했다.

검증 결과:

- `CharacterStyleTests`: 2,880개 프로필의 중복 없음·ID 안정성·플레이어 배색 제외·유효 색상.
- `ArtAssetTests`: 전체 카탈로그와 클립, 스키닝된 머리의 6개 표정 차이, 표정 변경 시 머리카락 형상 보존.
- Blender 재가져오기: 기존 액션 154개 데이터블록(사용 144개)의 키프레임 해시 보존과 주민 GLB의 기본 표정/스킨 위치 일치.
- 실제 렌더러에서 같은 파츠/표정/포즈를 쓰는 색상 15종을 추가 표시했을 때 메시 빌드 0회, 캐시 미스 0회.
- 저장을 막은 복사본의 게임 검사: 기존 파츠 보존, 두 번 동기화한 뒤 팔레트 유지, 실제 OpenGL 오류 없음.
- Release/Debug 빌드 완료.

180프레임 이동 검사에서 준비 60프레임 제외 후 평균 16.65ms, p95 17.21ms, 최대 17.71ms였다. 최초 사용을 포함한 최대 프레임은 588ms로, 첫 로딩/첫 포즈 준비의 지연은 남아 있다. 짧은 고정 시간 간격 검사이며 장시간 플레이의 보장은 아니다. 결과는 `docs/performance/2026-11-02-character-variation.json`에 기록했다.

`Catalog/character_style_catalog.json`은 다음 적용 작업용 색상/표정 인덱스와 플레이어 조합이다. `tools/Export-CharacterStyleCatalog.py`가 C++의 기준 팔레트에서 생성한다. `tools/Add-NPCExpressions.py`는 공용 머리의 모프와 GLB를 갱신하며, 기존 캐릭터 재생성 도구도 같은 함수를 호출한다. `Catalog/character_style_validation.json`에 현재 검사 결과를 저장했다.

실제 게임 렌더러 미리보기는 `Previews/Rigged/10_Character_Individuality.png`, `11_Character_Expressions.png`, `12_Character_Individuality_In_Game.png`이다. 10번에서 첫 캐릭터가 플레이어다.
