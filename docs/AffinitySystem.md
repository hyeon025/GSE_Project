# NPC와 플레이어 호감도

월드 HUD의 **호감도 H** 버튼 또는 **H 키**로 순위 화면을 연다. NPC와 대화 중에는 현재 호감도, 관계 단계, 신뢰, 마지막 증감을 함께 표시한다. 순위는 생존 NPC 기준이며 높은/낮은 순, 소속 마을, 대화한 NPC 필터와 페이지 이동을 지원한다. 마을 버튼을 누르면 전체 → 각 마을 순으로 전환한다. 동점은 고정 NPC ID 순이다. 행을 선택하면 최근 변화 이유와 대화 보상 대기시간을 볼 수 있다. Esc로 닫는다. 순위 화면에서는 플레이어 이동만 멈추며 월드 시뮬레이션은 계속된다.

## 호감도 규칙

NPC의 기존 `relationship` 값을 그대로 사용하며 범위는 -100~100이다. 기존 저장의 관계를 초기화하지 않는다.

| 행동 | 변화 | 조건 |
|---|---:|---|
| 대화 | +5 | 같은 NPC에게 시뮬레이션 60초마다 한 번 |
| 빵 나누기 | +25 | 빵 1개 소비 |
| 치료·보호 | +35 | 대화한 NPC에게 약초 1개, NPC별 최초 1회 |
| 다른 삶 지원 | +15 | 호감도 50 이상, 목재 2개, NPC별 최초 1회 |
| 함께 수련 | +5 | 기존 인접 능력·신뢰·기력 조건 충족, 기술 최초 습득 |
| 거래 | +2 | 성공한 거래만, 같은 NPC에게 30초마다 한 번 |
| 위협 | -40 | 기존 위협 선택지 |
| 공격 | -15 | 실제로 성공한 공격만 |

한계값에서는 실제로 변한 만큼만 기록한다. 예를 들어 90에서 빵을 주면 +10만 기록한다. 대화와 거래는 대기 중에도 가능하지만 호감도가 중복 적립되지 않는다. 대기시간은 NPC별로 저장되며 대화창 재진입·게임 재실행으로 초기화되지 않는다. 시간 경과에 따른 자동 감소는 없다.

관계 단계는 적대(-100~-50), 경계(-49~-1), 중립(0~24), 우호(25~49), 친밀(50~74), 깊은 유대(75~100)다. 신뢰는 호감도 25/50/75에서 1/2/3으로 바뀌며, 공격·위협으로 감소할 때도 즉시 갱신한다. 상인은 기존 규칙대로 호감도가 음수면 거래하지 않고, 우호 이상인 약탈자는 플레이어를 먼저 약탈 대상으로 고르지 않는다. 플레이어가 먼저 공격했을 때의 반격은 유지한다. 일반 대사는 관계에 따라 달라지며 스토리 인물의 전용 대사가 우선한다.

## 웹 모니터

새 실행 파일로 게임을 실행하고 프로젝트 루트에서 다음을 실행한다.

```powershell
powershell -File .\tools\Start-Monitor.ps1 -Background
```

기본 주소는 `http://127.0.0.1:8765/`이며 포트 사용 중이면 스크립트가 출력하는 주소를 사용한다. 일반 Python 3.9+를 찾지 못하면 설치된 Blender의 번들 Python도 확인한다. 직접 지정하려면 `-PythonPath "Python 실행 파일의 절대 경로"`를 사용한다. 패키지 설치는 필요 없다.

**플레이어 호감도 순위**에서 이름/ID 검색, 소속 마을, 관계 단계, 생존/대화한 NPC/사망 기록 필터, 정렬과 10명 단위 페이지를 지원한다. **호감도 변화 내역**에는 원인·증감·이전값·현재값·시각이 나오며 NPC를 선택한 뒤 해당 NPC의 이력만 볼 수도 있다. 생존 NPC 평균, 우호 이상 인원, 경계/적대 인원도 집계한다. 기존 NPC 상세에도 호감도와 신뢰를 표시한다.

모니터는 읽기 전용이며 기본 1초 주기로 수신한다. 게임 종료/갱신 지연/연결 끊김 시 기존 상태 표시를 유지하고 실시간으로 가장하지 않는다. 예전 실행 파일의 스냅샷도 관계 수치로 순위를 표시하되 새 이력·대기시간은 미수신으로 표시한다.

## 저장과 성능

- 저장 포맷은 `GSE_WORLD 8`이며 `AFFINITY 1` 확장에 대화·거래 시각, NPC별 마지막 변화, 최근 128건의 전역 변화 이력을 저장한다. 기존 버전 1~7 로딩 경로와 아바타 프로필을 유지한다. 옛 행동의 이유·시각은 만들어 넣지 않는다. 버전 8 저장은 이전 실행 파일에서 읽을 수 없다.
- 모든 호감도 변경은 `Affinity::Apply`에 모아 수치, 신뢰, 이력, 저장 dirty 상태가 함께 갱신된다. 실패한 거래·공격과 사망한 NPC는 변경하지 않는다.
- 추가 시뮬레이션 순회나 매 프레임 정렬을 하지 않는다. 게임 순위는 화면이 열릴 때, 필터/호감도 변경 시, 또는 열린 동안 최대 1초 간격으로 재계산한다. 전역 이력은 128건으로 제한하고 NPC별 마지막 변화는 별도로 보관한다. 사망자는 기본 순위에서 빠지며 웹의 사망 기록 포함 필터와 이력에서는 확인할 수 있다.
- 스냅샷의 기존 `npcs[].relationship`을 유지한다. `met`, `trust`, `affinity.{tier,lastChange,lastDelta,lastReason,talkCooldown,tradeCooldown}`과 최상위 `affinity.{min,max,historyLimit,events}`를 추가했다. 이력 항목은 `id,npcId,reason,reasonId,before,after,delta,time`이다. 시각은 `simulationTime`과 같은 기준이다.

## 검증

- `tests/AffinityTests.cpp`: 상하한, 실제 변화량, NPC별 대기시간, 사망자 제외, 거래 실패, 공격 후 신뢰, 우호 NPC 선제 약탈 방지, 정렬·필터, 이력 상한, 버전 6/7 마이그레이션, 버전 8 저장 왕복, 손상 저장 거부, 모니터 JSON.
- `tests/AffinityUiTests.cpp`: 실제 게임 액션·키보드·마우스 처리와 HUD 렌더링. 대화/빵/치료/위협, 중복 치료 거부, 순위 선택·정렬·마을 필터·페이지·빈 결과·닫기. 960×640 및 1440×900 확인.
- 실제 플레이어 저장을 덮어쓰지 않고 `x64/affinity-tests`의 별도 파일과 숨긴 GL 창을 사용한다.
