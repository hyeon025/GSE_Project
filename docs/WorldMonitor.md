# 로컬 월드 모니터

기본 접속 주소: **http://127.0.0.1:8765/**. JSON은 `/api/state`, 서버와 데이터 연결 진단은 `/api/health`에서 조회한다. 게임과 모니터 서버가 실행 중이어야 실시간으로 갱신된다.

## 5개 마을과 주민 이름

잿빛, 종탑, 강변 마을을 유지하고 기존 도로 사이에 안개숲·검은나루 마을을 추가했다. 중심 생활권의 범위는 그대로다. 새 게임은 각 마을 8명, 총 40명의 일반 주민으로 시작한다. 안개숲은 구도자가 많고 검은나루는 약탈자가 많은 초기 구성이며, 이후 성향은 실제 주민 상태로 집계한다.

NPC 이름은 저장된 고정 ID에서 결정되므로 재실행·이동·직업 변경으로 바뀌지 않는다. `npcs[].name`, `npcs[].villageName`, `villages[].name`을 JSON에 추가했다. `village`는 소속, `presentVillage`는 현재 위치, `destination`은 이동 목적지로 구분한다. 대시보드는 수신한 마을 목록으로 필터를 구성하고 이름·ID·마을·직업·활동으로 검색한다. 이름이 없는 이전 스냅샷은 NPC ID로 표시한다.

`SOCIETY 3`은 마을 수와 주민 배치 완료 마을 수를 저장한다. 기존 버전 1·2의 세 마을 주민·금고·사망 기록은 유지하고 새 마을에만 주민 16명을 한 번 추가한다. 이미 사망한 주민을 다시 채우지 않는다. 총 NPC 레코드 상한 200,000개에 여유가 없으면 추가 배치는 보류한다. 추가된 건물 안에 기존 플레이어나 생존 NPC가 겹치면 안전한 마을 중심으로 옮긴다. 이전 실행 파일로 새 저장을 읽을 수는 없다.

## 마을 분위기와 살인 소문 확장

NPC 상세, 마을 집계, 몹 수, 사건 목록에 마을 성향·분위기 및 별도의 살인 소문 목록을 추가했다. 게임의 실제 상태에서 계산하며 HTML 화면은 `/api/state`의 JSON으로 갱신된다.

마을 `character`는 0 무인, 1 약탈자 거점, 2 선량한 마을, 3 상업 마을, 4 구도자 마을, 5 혼합 마을이다. 약탈자 직업 또는 약탈 가중치 0.6 초과 주민이 40% 이상이면 약탈자 거점으로 본다. 수호자·치유사가 50% 이상이고 평균 약탈 가중치가 0.35 미만이면 선량한 마을이다. 상인 또는 구도자가 1/3 이상이면 해당 성향으로 표시한다. 위 순서로 판정하며, 현재 월드에 해상 활동이 없으므로 해적마을에 대응하는 성향은 약탈자 거점으로 표현한다.

마을 `mood`는 0 적막, 1 혼란, 2 궁핍, 3 불안, 4 평온이다. 주민이 없으면 적막, 교전·최근 120초 내 인근 사망·위급 주민 25% 이상이면 혼란, 재고 10 미만 또는 금고 20 미만이면 궁핍, 약탈 성향 주민 25% 이상 또는 유통 소문이 있으면 불안, 나머지는 평온이다. 판정 근거인 `raiders`, `averageRaidWeight`, `recentDeaths`, `heardRumors`도 JSON에 포함한다. 이는 관측 지표에 따른 분류이며 NPC 전체의 도덕성을 확정하는 판정은 아니다.

`rumors`는 실제 NPC/플레이어의 폭력 사망 이벤트에서 생성된다. 각 항목은 `id`, `kind: "murder"`, `actor`, `victim`, `village`, `witnesses`, `time`, `age`, `x`, `y`, `reachMask`, `active`를 담는다. 발생 지점에서 가장 가까운 마을을 기록하고, 가해자·피해자를 제외한 반경 180 안의 생존 NPC를 목격자로 집계한다. 시야 차폐나 개별 NPC 대화에 의한 검증은 아직 구현하지 않았으며 목격자가 없으면 미확인 전언으로 표시한다. 정당방위 등 법적 맥락을 판정하지 않고 폭력 사망에 대한 소문으로 취급한다.

전파는 시뮬레이션 시간 기준이다. 발생 직후 인근 마을, 30초 뒤 해당 마을에서 가장 가까운 다른 마을, 60초 뒤 전체 마을에 퍼진다. `reachMask`의 비트 0/1/2/3/4는 잿빛/종탑/강변/안개숲/검은나루 마을을 뜻한다. 300초 후 `active`가 false로 바뀌며 마을의 유통 소문 집계에서 제외된다. 필터를 해제하면 지난 소문도 조회할 수 있다. 이 전파는 프로토타입의 시간 규칙이며 개별 주민 간 전달 AI는 아니다.

소문은 일반 사건 128건과 별도로 최근 64건을 저장한다. 소문 저장은 `SOCIETY 2`부터 지원하며 현재는 마을 확장을 포함한 버전 3으로 저장한다. 기존 `SOCIETY 1`은 소문이 없는 상태로 읽는다. 예전 사건에는 당시 위치·목격자 정보가 없으므로 소문을 소급하여 만들지 않는다. JSON 스키마 1에는 선택적인 확장 필드로 추가하여 기존 스냅샷도 대시보드에서 읽을 수 있다.

화면에서는 전파 마을과 활성 여부로 소문을 필터링하고, 실제 사건 목록은 공격·사망, 거래·사냥, 계승·치료·깨달음으로 분류해서 볼 수 있다.

## 구성

`게임 상태 → JSON 스냅샷 → 로컬 HTTP 서버 → HTML 대시보드`

게임은 1초마다 `%LOCALAPPDATA%\GSE_Project\Monitor\snapshot.json`을 갱신한다. 브라우저는 기본 1초 간격으로 `GET /api/state`에서 JSON 메시지를 수신한다. WebSocket이나 게임 제어 API가 아닌 읽기 전용 HTTP 모니터링이다. 대시보드의 주기는 1/2/5초 중 선택할 수 있다.

게임 스레드가 데이터 직렬화를 담당하고, 파일 쓰기는 별도 스레드에서 수행한다. 대기열은 최신 메시지 하나만 유지한다. 임시 파일 기록 후 원자적으로 교체하여 쓰기 도중의 JSON이 노출되지 않도록 한다. 쓰기 실패는 콘솔에 기록하며 이전 정상 파일을 보존한다.

## 실행

1. 변경된 게임을 사용자가 빌드하고 실행한다.
2. 프로젝트 루트의 PowerShell에서 다음 명령으로 모니터 서버를 실행한다. Python 3.9 이상이 필요하며 별도 패키지는 필요 없다.

```powershell
powershell -File .\tools\Start-Monitor.ps1
```

3. 브라우저에서 `http://127.0.0.1:8765/`를 연다.
4. 서버를 종료하려면 서버 터미널에서 `Ctrl+C`를 누른다.

터미널을 유지하지 않고 실행하려면 다음 명령을 사용한다.

```powershell
powershell -File .\tools\Start-Monitor.ps1 -Background
```

동일 프로젝트와 스냅샷을 사용하는 서버가 이미 실행 중이면 재사용한다. 다른 프로그램이 포트를 사용하면 다음 20개 포트 범위에서 빈 포트를 찾으므로 출력된 실제 URL로 접속한다. 시작 포트는 `-Port 8766`, 입력 파일은 `-Snapshot "절대 경로"`로 지정할 수 있다. 포트 점유 프로세스를 임의로 종료하지 않는다.

백그라운드 로그는 `%LOCALAPPDATA%\GSE_Project\Monitor\server-포트.log`와 `server-포트.error.log`에 기록한다. 백그라운드 서버를 종료하려면 실행 시 출력된 PID를 확인한 후 `Stop-Process -Id 해당PID`를 사용한다.

PowerShell 스크립트 실행이 제한된 환경에서는 정책을 변경하지 않고 Python을 직접 호출할 수 있다.

```powershell
py -3 .\tools\monitor_server.py --port 8765
```

다른 스냅샷 파일을 조회하려면 Python 명령의 `--snapshot "절대 경로"`를 사용한다. `monitor/index.html`을 `file://`로 직접 여는 방식은 지원하지 않는다. 브라우저의 파일 접근 보안 제한을 우회하지 않고 동일 출처 HTTP로 JSON을 받는다.

## 표시 정보

- 전체: 생존/사망/전체 NPC 수, 현재 전투의 살아 있는 몹 수, 등장 중 몹과 보스, 플레이어 체력·은화·사망, 누적 거래·약탈 명중·NPC 사망.
- NPC: 이름, ID, 생존, 직업, 목표, 행동, 소속 마을, 실제 위치, 행선 마을, 체력, 은화, 물품, 깨달음, 약탈 가중치, 공격 대상, 능력, 전투력, 관계, 계승 관계.
- 마을: 생존 소속 주민과 현재 마을 영역 안의 인원, 체력 비율, 부상/위급 인원, 금고, 재고, 주민 자산, 물품, 깨달음, 직업별/행동별 인원, 교전 인원.
- 최근 사건: 시뮬레이션에 저장된 최근 128건. 기록을 추가 생성하거나 게임 상태를 변경하지 않는다.
- 지도: 중심 생활권 ±800 범위의 실제 주민 위치. 범위 밖 인원은 따로 집계하며 NPC 목록에는 그대로 나온다. 전투 중 플레이어의 별도 전투 좌표는 월드 지도에 혼합하지 않는다.
- 연결 진단: 마지막 수신 시각, 원본 데이터 경과 시간, 틱 증가율, 스냅샷 크기, HTTP 응답 시간, 실제 입력 파일 경로와 오류 원인. 틱 증가율은 연속 메시지 간 차이이며 렌더링 FPS가 아니다.
- 위험 및 경제: 위급 NPC, 교전 및 플레이어 추격 인원, 마을의 최근 사망·재고 부족·금고 부족 경고, 총 은화·재고·물품·깨달음·유통 소문. 총 은화는 사망 NPC의 보유 기록까지 포함한다.
- 플레이어 보호: 약탈 유예 시간과 피격 후 회복 시간. `player.raidGraceSeconds`, `player.hitRecoverySeconds`를 추가했으며 이 필드를 내보내는 게임으로 빌드해야 표시된다. 이전 실행 파일에서는 0으로 추정하지 않고 `미수신`으로 표시한다.

NPC 목록은 검색, 마을·직업·생존 필터, 정렬, 50명 단위 페이지를 제공한다. NPC ID나 지도 점을 선택하면 상세 정보를 표시한다. 다운로드 버튼은 마지막 수신 스냅샷을 JSON 파일로 내려받는다.

### 집계 정의

- 마을 주민/자산/직업/체력: 해당 마을에 **소속된 생존 NPC** 기준. 외출 중인 주민도 포함한다.
- 현지 인원: 마을 반경 안에 실제로 위치한 **생존 NPC** 기준. 다른 마을에서 온 방문자도 포함하며 플레이어는 제외한다.
- 위급: 최대 체력의 35% 미만. 부상은 최대 체력 미만이며 위급 인원을 포함한다.
- 교전: 대상 ID가 지정된 주민 수. 약탈 사건 수와 같지 않다.
- NPC 전체: 사망 기록을 포함한 누적 NPC 레코드 수.
- 몹: 현재 활성 전투 세션의 `health > 0`인 적. 등장 대기 적과 보스도 포함하며 각각 부분 집계를 별도 제공한다. 사망 적은 제외한다.
- 저장된 비활성 경작지/스토리 적은 `storedFieldAlive` / `storedStoryAlive`에만 나오며 현재 몹 수에는 합산하지 않는다.
- 현재 오픈월드 사냥은 추상 시뮬레이션이므로 개체형 야생 몹 수는 0이다. 사냥꾼이나 약탈자 NPC를 몹으로 중복 집계하지 않는다.

## JSON 계약

`GET /api/state` 응답은 다음 형태다. 아래는 구조 예시이며 실제 NPC 레코드는 생략했다.

```json
{
  "status": "live",
  "ageSeconds": 0.3,
  "snapshot": {
    "type": "world.snapshot",
    "schemaVersion": 1,
    "session": "123456789",
    "sequence": 42,
    "timestampMs": 1791200000000,
    "paused": false,
    "stopped": false,
    "worldTime": 40,
    "simulationTime": 40,
    "tick": 400,
    "counts": {"npcAlive": 40, "npcDead": 0, "npcTotal": 40, "mobs": 0, "spawning": 0, "bosses": 0, "wildlifeEntities": 0},
    "player": {"health": 100, "maxHealth": 100, "gold": 30, "deaths": 0, "x": 0, "y": 0},
    "combat": {"active": false, "story": false, "phase": -1, "encounter": 0, "storedFieldAlive": 0, "storedStoryAlive": 0},
    "statistics": {"trades": 0, "raidHits": 0, "npcDeaths": 0},
    "villages": [],
    "npcs": [],
    "events": []
  }
}
```

`session`은 게임 실행마다 달라지는 문자열, `sequence`는 해당 실행의 단조 증가 메시지 번호다. 큰 세션 값을 JavaScript 숫자로 변환하지 않는다. `timestampMs`는 Unix 밀리초이며 화면은 로컬 시각으로 표시한다. 유한하지 않은 실수는 유효한 JSON `null`로 내보낸다.

직업 ID: 사냥꾼 0, 상인 1, 약탈자 2, 구도자 3, 수호자 4, 치유사 5.
행동 ID: 회복 0, 사냥 1, 거래 2, 이동 3, 약탈 4, 명상 5, 순찰 6, 치료 7, 방어 8.
목표 ID: 체력 0, 재산 1, 깨달음 2. 마을 ID: 잿빛 0, 종탑 1, 강변 2, 안개숲 3, 검은나루 4.
능력 ID: 육체 0, 감각 1, 정신 2, 운명 3, 물질 4, 생명 5.
NPC 대상 ID: 0은 없음, -1은 플레이어, 양수는 NPC ID.

## 연결 상태와 제한

- `waiting`: 게임이 아직 스냅샷을 생성하지 않았다.
- `live`: 최근 5초 내 데이터가 있으며 시뮬레이션이 동작 중이다.
- `paused`: 최근 데이터지만 게임이 일시정지 상태다. 대화창만 연 경우는 생활 시뮬레이션이 계속되므로 live다.
- `stale`: 마지막 발행으로부터 5초 이상 경과했다. 강제 종료, 게임 응답 지연 등을 포함한다.
- `stopped`: 정상 종료 시 마지막 메시지에 종료 상태가 기록되었다.
- `error`: JSON 파손, 지원하지 않는 버전, 파일 접근 실패, 64 MiB 제한 초과 등이다.
- HTTP 서버 연결 실패는 대시보드에서 별도로 표시한다. 마지막 정상 데이터는 남기되 실시간 상태로 표시하지 않는다.

서버는 `127.0.0.1`에만 바인딩한다. 지정된 HTML/CSS/JS와 상태 API만 제공하고, 임의 파일 탐색 및 교차 출처 API 접근을 허용하지 않는다. 게임 명령이나 저장 수정 API는 없다. 여러 게임 인스턴스는 동일한 스냅샷 경로를 공유하므로 동시에 실행하지 않는 것을 전제로 한다.

수집/직렬화는 초당 한 번 전체 NPC를 순회하므로 O(N) 비용이 있다. 파일 쓰기만 비동기이며 직렬화까지 무비용인 것은 아니다. 대규모 월드에서는 증분 메시지, 공간별 구독, 별도 샘플링 최적화가 필요하다.

## 검증

`tests/MonitorSnapshotTests.cpp`: 집계, 방문자 구분, 사망 기록, 활성/비활성 전투, 보스/등장 대기, 소수점 로케일, null 수치, 종료 플래그 검사.
`tests/test_monitor_server.py`: 대기/정지/지연, JSON 오류 복구, HTTP 응답, Host/Origin 제한과 임의 파일 차단 검사.

사용자가 실행할 Python 테스트 명령:

```powershell
py -3 -m unittest discover -s tests -p test_monitor_server.py
```

실시간 모니터링 요청에 따라 로컬 서버 실행, 실제 게임 메시지의 sequence/tick 증가, HTTP 응답 및 브라우저 표시를 확인했다. 게임 빌드와 테스트 스위트 실행은 수행하지 않았다.
