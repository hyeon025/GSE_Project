# 머리카락 가림, 연속 보행, 프레임 지연 수정

## 머리카락 사이로 보이던 피부

캐릭터가 사용하는 2D 투영 삼각형을 면 단위로 정렬하면 교차하는 머리카락·피부 면의 일부를 올바르게 가릴 수 없었다. 머리카락이 실제로 존재하는 픽셀에서도 머리 피부가 위에 그려질 수 있었다. `Audit-HairCoverage.py`의 정수리 표면 검사 125,400개에서는 실제 덮임 누락이 없었다. `.blend`와 GLB, 파트 이름, 본, 키프레임을 변경하지 않고 렌더링 원인을 수정했다.

캐릭터의 조립된 전체 포즈에서 정점별 카메라 깊이를 보관하고 GPU 깊이 버퍼로 픽셀마다 가까운 면을 선택한다. 서로 다른 캐릭터·건물은 기존 화면 그리기 순서를 유지하도록 인스턴스별 깊이 구간을 사용한다. 인스턴스 배칭을 유지하며 HDR와 MSAA 타깃에는 32비트 부동소수 깊이 버퍼를 추가했다. UI와 월드 사이에서도 깊이가 섞이지 않도록 매 프레임 타깃을 초기화한다.

팔레트 캐릭터에는 자동 적용하며 전투 몹에도 적용한다. 건물 등 정적인 환경의 기존 면 정렬은 유지한다. 캐릭터 내부를 GPU에서 판정하므로 포즈마다 수행하던 CPU 삼각형 교차 정렬도 생략한다. 포즈 캐시 버전을 갱신해 이전 정렬 결과를 재사용하지 않는다.

5종 머리카락 × 2종 머리 × 4방향의 실제 GPU 결과를 별도 CPU 픽셀 깊이 기준과 비교했다. 화면 안에 모든 검사 대상이 들어오는지와 조합별 최소 1,000개 검사 픽셀도 확인했다. 남성 124,434개, 여성 123,947개의 불투명 내부 픽셀에서 색 분류 오차와 머리카락 위로 잘못 그려진 피부는 모두 0개였다. 정답이 하나로 정해지지 않는 근접 깊이 동점 6개/머리와 MSAA 경계 혼합색 픽셀은 별도 집계해 제외했다. 선행 인스턴스 4,096개 뒤의 교차 면, 그리기 순서 반전, 배치 중간 제출, 서로 다른 캐릭터와 UI의 가림 순서도 통과했다.

## 이동 중 멈춰 보이던 다리

이동 거리에 따른 `CharacterMotion` 위상 자체는 진행하고 있었다. 그러나 캐릭터별 비동기 포즈 요청이 FIFO 대기열에 쌓여, 플레이어도 NPC 뒤에서 기다리는 동안 이전 포즈를 반복 표시했다. 같은 메시·방향·시간의 요청도 캐릭터가 다르면 중복 계산할 수 있었다.

단일 작업자는 유지하면서 플레이어 요청을 우선 처리하고, 동일한 포즈 키는 한 번 계산해 요청한 캐릭터들에 전달한다. 완료 순서는 캐릭터별 요청 번호로 관리해 다른 캐릭터의 오래된 결과가 최신 표시를 막지 않도록 했다. 원본 애니메이션과 보행 30Hz 샘플링은 유지한다. GPU 깊이 판정으로 포즈 계산 비용도 줄었다.

실제 OpenGL 다리 영역 픽셀로 24개 NPC가 포즈를 요청하는 상황에서 120프레임씩 검사했다. 위상은 실제 `CharacterMotion.Update`로 진행하고, 루프 경계 및 멈춘 뒤 달리기로 전환하는 경우도 검사한다.

| 검사 | 기존 서로 다른 다리 화면 / 최장 동일 화면 | 수정 후 |
|---|---:|---:|
| 걷기 | 7개 / 13프레임 | 30개 / 2프레임 |
| 달리기 | 9개 / 10프레임 | 22개 / 1프레임 |

30Hz 애니메이션을 60Hz 화면에 표시할 때 일부 인접 화면이 같은 자세인 것은 정상이다. 기존 코드를 별도 출력 폴더에 복사해 동일 검사에서 실패하는 것까지 확인했다.

## 추가 최적화

- 플레이어 이동 갱신에서는 NPC·배경 그래프 전체를 다시 동기화하지 않는다. NPC 표시 데이터는 렌더 단계에서 한 번 복사·보간한다.
- 고정된 마을 위치와 도로 연결을 한 번만 계산한다. 미니맵의 도로 마스크는 플레이어 좌표가 정확히 같으면 재사용하며, 이동 중에는 기존 위치에서 정확하게 다시 샘플링한다.
- 텍스트를 새로 만들 때 사용하는 Windows DC와 글꼴을 재사용한다. 글꼴은 렌더러당 최대 32개로 제한하고 종료 시 해제한다. 글꼴·크기·안티앨리어싱·픽셀 출력은 유지한다.

## 측정

RTX 4060 Ti, Release, 1440×900, 같은 저장 사본과 고정 이동 입력, 각 180프레임을 비교했다. 실제 게임의 갱신·HUD·렌더·스왑 경로를 사용하고 GPU 완료를 기다렸다. 벤치마크는 VSync 없이 수행하므로 아래 수치를 플레이 중 고정 FPS로 해석하지 않는다. 앞 60프레임을 제외한 반복 구간 수치다.

| 장면 | 항목 | 기존 | 수정 |
|---|---|---:|---:|
| 이동 | 평균 / p95 | 3.68 / 5.83ms | 3.43 / 4.63ms |
| 이동 | 최대 | 14.01ms | 5.95ms |
| 이동 | 게임 갱신 평균 | 0.229ms | 0.117ms |
| 대기 | 평균 / 최대 | 3.36 / 14.16ms | 3.14 / 5.50ms |

최초 프레임을 포함한 이동 최대치는 512ms에서 269ms로 줄었지만, 처음 파일·글꼴·GPU 자원을 준비할 때의 지연이 완전히 사라진 것은 아니다. 이 측정은 모든 인구 규모·전투·하드웨어에서 지연이 없음을 보장하지 않는다. 실 플레이 저장은 수정하지 않았다.

## 검증 코드

- `tests/ArtAnimationTests.cpp`: 실제 다리 픽셀의 연속 보행/달리기, 정지·재출발, NPC 요청 부하.
- `tests/PoseWorkerTests.cpp`: 동일 키 중복 제거, 캐릭터별 완료 번호, 큐 포화 시 플레이어 우선, 종료.
- `tests/HairDepthRenderTests.cpp`: 교차 면, 제출 순서, 서로 다른 캐릭터와 UI의 깊이 격리, 모듈형 머리/헤어의 실제 GL 출력.
- `tests/NpcPresentationTests.cpp`: 실제 플레이어 이동 갱신을 연속 호출해 주기 경계·재출발·정지를 검사하고 NPC 보간/저장 좌표 보존도 검사.
- `tests/RendererTextCacheTests.cpp`: 600개 문자열·48개 크기로 캐시 퇴거를 유도한 뒤 RGBA 일치, GDI 핸들 상한·종료 정리 검사.
- `tests/RoadSamplingTests.cpp`: 기존 도로 계산과 수만 개 표본·경계·부동소수 인접값의 결과가 완전히 같은지 검사.
- 기존 `WorldSimulationTests`, `CharacterVisualTests`, `RenderBatchTests` 회귀 검사.
