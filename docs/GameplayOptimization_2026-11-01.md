# 실제 플레이 끊김 개선 · 2026-11-01

캐릭터만 그리는 이전 테스트로는 실제 플레이의 끊김을 설명하지 못했다. 이번에는 사용자 세이브의 복사본으로 지형·풀·마을·NPC·게임 업데이트·HUD·실제 `Display`와 `glutSwapBuffers`를 실행했다. 원본 세이브는 변경하지 않았다.

## 적용한 기술

1. **포즈 생성 비동기 처리**: CPU 스키닝·면 조명·투영·정렬을 전용 작업자 한 개로 처리한다. 새 포즈가 준비되는 동안 같은 외형·방향·클립의 최근 포즈를 재사용한다. 이동과 입력 업데이트는 계속 진행한다. 대기 요청은 외형별 최신 요청으로 합치고 128개, 완료 결과는 8개로 제한한다. OpenGL 호출과 캐시 관리는 계속 주 스레드에서 실행한다. 늦은 결과가 최근 표시 포즈를 덮지 않도록 요청 순번을 비교한다. 최초 외형은 동기 생성하므로 첫 표시 비용은 남는다.
2. **화면 밖 캐릭터 제외**: 사람의 모델 계산 전에 투영 위치와 보수적인 180×배율 여유 영역을 검사한다. NPC 시뮬레이션·충돌·사회 활동은 계속 실행된다.
3. **배치 정점 낭비 감소**: 1,024정점보다 큰 메시가 있는 배치의 패딩 상한을 8배에서 2배로 줄인다. 작은 도형 배치는 기존 한도를 사용한다. 배치 shader uniform 위치도 초기화 때 저장한다.
4. **공간 검색과 계산 재사용**: 장애물 타일 8,192개 캐시, 장애물이 아닌 타일의 조기 제외, 집 점유표 일괄 구성, 65단위 격자의 NPC 이웃 뉴스 검색을 적용한다. 기존 처리 순서와 결과를 유지한다.
5. **Debug 렌더링 최적화**: Art/Renderer/CharacterMesh 구현 파일은 Debug에서도 최적화해 F5 실행의 포즈·정점 처리 비용을 줄인다. 게임 로직 파일은 기존 Debug 설정을 유지한다. 최적화된 렌더링 함수의 일부 지역 변수는 디버거에서 표시되지 않을 수 있다.
6. **실제 프레임 계측**: CSV에 `build_mode`, `game_update_ms`, `previous_swap_ms`를 추가했다. 업데이트 시간에는 실제 `Idle`의 시뮬레이션·모니터 게시·자동저장 비용이 포함된다. `previous_swap_ms`는 직전 화면 교체의 대기 시간이다. 요약 도구는 구버전 CSV도 계속 읽는다.

모델 폴리곤·재질·HDR/블룸·기본 해상도는 낮추지 않았다. 부하가 클 때 표시 포즈가 잠시 늦게 갱신될 수 있으며, 이는 주 스레드의 긴 정지를 피하기 위한 처리다.

## 실제 게임 루프 측정

RTX 4060 Ti, 1440×900, MSVC x64 Release(`/O2 /MD`), 기존 Art 파일과 기본 HDR 설정. 원본 앱 소스를 포함한 `tests/PlayLoopBenchmark.cpp`에서 실제 `Update → Display → HUD → SwapBuffers`를 실행했다. 각 모드 180프레임 중 앞 60프레임을 제외한 120프레임을 비교했다. 화면 교체의 VSync 대기도 포함된다.

| 장면 | 수정 전 평균 / p95 / 최대 | 수정 후 평균 / p95 / 최대 |
|---|---:|---:|
| 저장 위치 정지 | 29.17 / 76.85 / 82.18ms | 16.65 / 16.94 / 17.56ms |
| 네 방향 이동 | 29.32 / 77.63 / 98.32ms | 16.65 / 16.87 / 17.05ms |
| 몹 24개체 전투 | 16.64 / 16.92 / 17.27ms | 16.64 / 16.87 / 20.59ms |

정지·이동에서 반복되던 긴 프레임이 줄었고 검사 구간 평균은 약 60FPS였다. 전투는 수정 전에도 이 짧은 검사에서 약 60FPS였으며 수정 후에도 유지됐다. 전투 테스트에는 보스 1개체와 테스트 전용 무적을 사용해 도중 사망으로 부하가 사라지지 않게 했다.

이번 최종 측정의 첫 사용 비용을 포함한 최대값은 정지 약 77ms, 이동 약 181ms, 전투 약 84ms다. 모든 최초 로딩 정지를 없앤 것은 아니다. 각 검사는 고정 시뮬레이션 간격의 3초 구간이며, 장시간 플레이 전체를 보장하는 수치는 아니다. 자동저장과 모니터 게시를 테스트에서는 차단했다. 실제 실행 로그의 새 시간 항목으로 그 비용을 구분할 수 있다.

최신 사용자 로그(`2026-11-01 01:24`)의 평균 렌더 CPU 시간은 403.08ms였다. 이 값은 위 Release 전후 비교와 다른 실행 조건이므로 직접 감소율을 계산하지 않았다.

결과 데이터: `docs/performance/2026-11-01-gameplay.json`.

## 독립 검사와 빌드

- 혼합 배치: 평균 1.687→0.616ms, p95 2.235→0.790ms, 제출 정점 약 75% 감소, 최종 RGBA 완전 동일. `docs/performance/2026-11-01-padding.json`.
- 350명 신규 월드 시뮬레이션 1,200회: 평균 0.473→0.128ms, p95 3.569→0.837ms. 전후 최종 사회/NPC 직렬화 상태 SHA256 동일. 실제 세이브 전체 프레임과는 별도 검사다.
- `WorldSimulationTests`, `ArtAssetTests`, `RenderBatchTests`, `PoseWorkerTests` 통과. 작업 요청 합치기·중복 작업 억제·종료, 기존 장애물/뉴스 결과와의 일치를 검사했다.
- 실제 게임 루프의 정지·이동·전투에서 OpenGL 오류 검사 통과.
- x64 Release와 Debug 빌드 성공. 기존 숫자 변환 경고는 남아 있다.
- 원본 세이브와 격리된 테스트 복사본의 SHA256 일치를 확인했다. 게임 저장 포맷은 변경하지 않았다.

## 사용 및 재측정

최신 실행 파일: `x64/Release/SimpleGame.exe`. Debug 실행 파일도 갱신했다.

재측정 예:

```powershell
.\tools\Measure-Gameplay.ps1 -SavePath 'C:\Users\user\AppData\Local\GSE_Project\world_v1.txt' -Mode move -Label play-check
```

`idle`, `move`, `combat` 모드를 사용할 수 있다. 지정한 세이브를 `x64/perf/<label>-data`로 복사하고, 숨겨진 OpenGL 창으로 검사하며 원본 저장을 차단한다. 결과는 `x64/perf/<label>.txt`와 격리된 CSV에 남는다. Visual Studio C++ 도구와 freeglut/glew DLL이 필요하다.
